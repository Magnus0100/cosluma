# 单一生产流程性能

唯一入口为 `Backend.task_plan/start_task → creative_task → production_coordinator → single_source_workflow`。桌面入口使用同一安装包；原景增强和局部编辑复用这条执行与保存链。

## 计时与复现范围

公开文档说明当前计时合同与复现方式，不保存私人照片的一次性实跑账本。具体耗时以实际工程的 `outputs/timings/` 记录为准，公开复现结果应使用获准素材并说明硬件、模型/runtime 身份、输入尺寸、任务模式和缓存状态。

首次准备、缓存重放和服务冷启动分别记录。只有输入、任务、模型和缓存状态相符的请求才能直接比较；子模块优化不能未经整条流程复测就换算成总耗时收益。物理内存与系统提交余量分别观察，并标明采样覆盖的阶段。

失败请求保留真实提交数及结果未知状态；后续成功不重写旧失败为成功，也不重置额度。

## 当前生成与区域计时

scoped 默认从原片浮点基线开始，由模型选择首次操作；独立审片后最多两轮通常改进，另有一次仅允许零生图工具或停止的收尾决策。默认单候选上限仍为三次图像，视觉上限为十次；首次编辑通过只用四次视觉且不执行条件节点。收尾不增加生图额度，模型根据实际图选择工具或停止，未知与停止决策均占用该轮，重开不刷新。显式只给 maximum_improvements 的一次或零次偏好不增加收尾轮次。阶段账本区分视觉设计、模型传输、CPU 摄影处理、外观冻结、渲染、独立审片、工具决策与复审及最终保存。CPU 工具执行由真实 tool call 证明，新增生图为零；外部实际用量取来源账本，缓存复审不重复计请求。自动与手动任务共用 session 和工具，不建立第二条计时链。

普通导入参考的原景增强与单区工具仍按各自 checked plan 记录 `source_scene_enhancement`、`regional_refinement` 和原生准备；不能将它们的测量套用为新默认链耗时。生成尺寸、区域覆盖和工作画布分开记录，大尺寸导出不能证明生成细节达到相机原生分辨率。

实际运行回执以当前工程 `workflow_timing` 为准，报告全程墙时、各节点包含／独占时间、缓存和提交次数。新手动纠偏只计本轮决策、工具与复审，父观察不算新调用。来源额度不随候选或重开重置；结果未知不自动重提，失败也保留已消费请求和时间。

## 账本、进度与估计

每次请求生成JSON和Markdown账本，module_totals汇总实际span；父节点与子节点包含时间不能重复相加。exclusive移除已测子节点，不把外部worker报告时间再次相加。计时包含请求体内阶段和检查点，排除最后遥测flush，具体范围保存在wall_scope。

SSE和轮询读取当前run绑定的实际阶段，显示阶段用时与累计用时。新 scoped 全程进度为不定比例，不用固定百分比假装已知完成量；条件步骤按真实执行更新。至少三次兼容成功记录才提供剩余时间中位数；输入、provider、图像/视觉模型、scope、iteration、图签名与缓存前缀须匹配。失败、取消、旧身份及不匹配样本不用于ETA。运行中账本标明快照，不能当作最终墙时。

启动按已恢复的服务选择初始化受管 Qwen 服务，不先加载 Beauty 再为 Qwen 卸载。现有 Qwen 服务启动不证明权重预热，首图加载与服务启动须分别计时。Beauty 由明确的人像操作按需加载、复用；新 scoped 生成不要求未用的原生模型就绪。不使所有模型永久常驻：使用现有受管空闲交接，真实资源状态不足时停止并保留输入。

优化顺序：消除未使用节点和重复准备，测量当前路线，再按独占热点优化。保留各路线真实的像素、alpha、材质与生成外观归属，以及冻结回放和保存精度；不能为提速把原人物 RGB 盖回完整生成外观。离线计时检查不证明真实生图资源峰值、艺术质量或独立安装性能，须分别实测。
