# 单一生产流程性能

唯一入口为 `Backend.task_plan/start_task → creative_task → production_coordinator → single_source_workflow`。桌面入口使用同一安装包；原景增强和局部编辑复用这条执行与保存链。

## 计时与复现范围

公开文档说明当前计时合同与复现方式，不保存私人照片的一次性实跑账本。具体耗时以实际工程的 `outputs/timings/` 记录为准，公开复现结果应使用获准素材并说明硬件、模型/runtime 身份、输入尺寸、任务模式和缓存状态。

首次准备、缓存重放和服务冷启动分别记录。只有输入、任务、模型和缓存状态相符的请求才能直接比较；子模块优化不能未经整条流程复测就换算成总耗时收益。物理内存与系统提交余量分别观察，并标明采样覆盖的阶段。

失败请求保留真实提交数及结果未知状态；后续成功不重写旧失败为成功，也不重置额度。

## 原景增强与区域计时

原景增强保留原生背景，不对已有真实细节整图低清重绘再超分。区域生成仅在新检查计划明确授予时执行，首版最多一个必要区域。阶段账本记录source_scene_enhancement、regional_refinement、准备／模型请求、渲染、编码与保存；实际调用、缓存命中及旧区域重用分开。

实际运行回执以当前工程 `workflow_timing` 为准，报告全程墙时、各节点包含／独占时间、缓存和提交次数。区域运行未知不自动重提；失败也要保留已经消费的请求及时间。

## 账本、进度与估计

每次请求生成JSON和Markdown账本，module_totals汇总实际span；父节点与子节点包含时间不能重复相加。exclusive移除已测子节点，不把外部worker报告时间再次相加。计时包含请求体内阶段和检查点，排除最后遥测flush，具体范围保存在wall_scope。

SSE和轮询读取当前run绑定的实际阶段，显示阶段用时与累计用时。里程碑不能因迟到事件倒退。至少三次兼容的成功记录才提供剩余时间中位数；输入、模型、预算与观察到的缓存前缀须匹配。失败、取消、旧身份及不匹配样本不能用于ETA。

Beauty只在实际加载完成后显示预热成功；Qwen配置、连接与模型加载分别记录。不使所有模型永久常驻：生成、Beauty与原生分析使用现有受管空闲交接，真实资源状态不足时停止并保留输入。

优化顺序：消除不必要的全景重绘／超分和重复准备，测量当前路线，再按独占热点优化。源像素、alpha、材质归属、冻结回放和保存精度不因性能目标而放松。技术运行、作品审片及人工批准仍分别记录。
