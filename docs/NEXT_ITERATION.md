# Demo 复盘与下一轮迭代

更新时间：2026-10-04

## 当前 Demo 的判断

两组 `outputs/demo/*/comparison.jpg` 已经足够证明最小架构成立：背景光斑、右上方暖光和雾化效果来自放大的 GPT 参考图，人物衣服与身体纹理主要来自高清原片经过 appearance operator 后的版本。`DSC02631` 的交接最自然；`DSC02634` 的强逆光也能保留，但人物边缘仍受默认椭圆 alpha 影响。

当前的 alpha 是固定的中心软椭圆（`center=(0.50,0.53)`、`radii=(0.26,0.47)`），因此它是流程占位而不是人物抠图。它在 02631 上基本覆盖主体，在 02634 上会让抬手、发丝和肩部边缘进入渐变区。渐变区会把 styled subject 与 reference subject 叠在一起，容易出现头发或手部的双边缘/亮度不一致。

appearance operator 本身没有看到明显的数值错误：局部网格从低分辨率估计，系数双线性插值后分块应用，输出仍保持原片尺寸；两个样本的全局通道缩放也符合参考图更亮、更暖的视觉结果。它的已知限制是拟合使用全画面像素，所以参考图中新增的太阳光和粒子会参与统计，可能让人物区域的全局增益偏强。

## 最值得继续的两项改动

### 1. 先把一次人工 mask 接入主流程

这是优先级最高的改动，成本低且直接改善可见瑕疵。沿人物轮廓刷一次白色主体、黑色背景的灰度 PNG，然后运行：

```powershell
& $py scripts/run_demo.py --sample DSC02634 --alpha path/to/DSC02634-mask.png --out-dir outputs/mask_trial
```

mask 应保留 0–255 灰度值：服装、手部和身体纹理取高值，脸部和发丝边缘保留中间灰度，背景光斑取 0。先只做 `DSC02634`，因为它能最快暴露抬手和强逆光下的边缘问题；确认交接自然后再复用到 02631。无需改动 operator 或引入新的 matting 模型。

需要把参考图中仍可见的人物轮廓一并覆盖，而不是只沿原片主体的内轮廓描边。当前多边形试跑在 `DSC02634` 的头顶产生了明显双边缘：轮廓顶部从约 `y=0.26` 开始，实际头发顶部约在 `y=0.17–0.20`。下一版应把头部向上、左右各留约 50–100px 余量，并把 feather 调到 30–50px 后再看边缘。

### 2. 将 operator 的拟合采样限制到主体信任区

在已有 mask 后，把 `fit_operator` 的 proxy 采样从全画面改成“主体高 alpha 像素 + 少量全画面像素”。这样新增的参考粒子不会把通道增益整体拉高，人物的肤色和服装纹理会更接近原片的局部统计。可以先用简单阈值（例如 alpha > 0.5）验证，不需要马上做鲁棒回归或多模型比较。

## 暂不投入的方向

- 不先下载大模型或更换整套 BGU；当前两组数据尚未显示 affine baseline 已经成为主要瓶颈。
- 不做 dense correspondence；两组图的主体坐标已经足够稳定。
- 不扩展测试框架。每轮只需生成一张 comparison，并检查人物轮廓、发丝和高光交接即可。

## 快速验收标准

下一轮只看四件事：

1. `DSC02634` 抬起的手和头发边缘没有明显双轮廓；
2. 黑色外套和白色马甲的原片纹理仍清楚；
3. 右上方太阳光、粒子和地面高光仍来自 reference；
4. 输出尺寸仍为 6336×9504，并在 `metadata.json` 中记录 alpha 来源。
