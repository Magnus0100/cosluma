# 可撤销形体调整

形体调整是已保存成片上的独立可选操作，默认关闭。风格、Beauty 强度、重光照和普通反馈不会开启它。当前合同允许选择脸部、腰部、手臂和腿部及各自请求幅度；模型无法从成片明确识别所选部位时应停止，不猜测画外身体。幅度是编辑请求，不是人体测量。

对于合成作品，先完成合成、调色、调光及人物环境融合，再保存成片并进入形体调整；U 指这张成片。塑形后复核已成立的受光、脸颈与头发过渡、衣物和背景线条。后续上游编辑产生的新成片需要新的塑形组与 U，不在旧形变结果上累积。当前普通反馈与形体结果的互操作边界仍见下文。

## 操作与可复核结果

1. 打开完整保存的成片，选择部位和幅度，检查任务，再计算候选。脸部单独使用确定性轮廓形变，零次生图；身体局部编辑至多提交一张图像。两者均至多三次视觉观察；规划不执行定位或像素计算。
2. 程序保留这一组调整开始前的完整母版 U。由候选 A 改为另一幅度 B 时，实际编辑输入仍是 U，不在 A 上累积变形。
3. 候选完成只显示同视口比较，取消保留当前版本。只有明确采用，才改变当前版本和重启后的选择。采用版本不等于人工批准画质。
4. 返回调整前版本走同一受检入口，不调用图像模型、视觉模型或 RAW 准备。先展示 U 的恢复候选，采用后保存关闭状态。浮点母版、预览和覆盖职责均应原样等于 U，不用逆变形或重新生成来近似恢复。
5. 保存、复制和便携工程拥有 U 与当前资产。原父工程不在、省略 RAW 时仍可执行零模型恢复。新的 apply 仍需要真实原片和原请求证据，不能续发未知请求额度。

失败、取消和迟到回调必须保留原当前版本。相同 U、部位、幅度和 provider 的未知请求不能换 run ID 重发。零覆盖区域严格等于实际输入 U 的浮点像素；生成外观只拥有真实覆盖。候选独立评价人物可信度、原创作收益和 `shaping_fulfillment`，不把生成成功或像素不同当作自然塑形完成。

显式选择脸部时，apply 还需要已注册的 CPU 人脸定位运行环境。规划只核验定位模型、Python 和 MediaPipe 元数据的当前身份，不执行定位。执行对实际 U 运行或复用同身份定位，再根据原生坐标的脸颊、下颌拓扑限定编辑带；中央面部、眼眉鼻唇以及面部包络内非编辑带区域位移严格为零。改力度复用匹配 U 的分析，不分析上一候选 A。缺失、多脸、退化、过小、出画或无有效位移时停止，不回退整脸矩形替换。body-only 不增加这项依赖，restore 仍不读取或运行分析模型。

脸部使用按眼轴对齐的规则网格权重形变：轮廓逐行最近网格节点作为带值约束（Dirichlet handle），保护区 P、包络之外与网格边界作为零锚点，自由节点解 Dirichlet 能量最小（有界调和权重，weight_operator=bounded_harmonic_mesh_weights）。场由边界数据界定，因此不会过冲或折叠；采样用 cv2.remap 双线性（interpolation=cv2_remap_bilinear_display_linear_RGB_and_G）。颜色和原生成来源覆盖 G 使用同一坐标与重采样；几何编辑支持不是新增生成透明度。零位移直接保留 U（不插值、逐位拷贝），映射越界、折叠、保护区泄漏、包络外改动及没有实际 RGB 变化均拒绝。

脸部与身体组合目前在检查阶段拒绝，不能悄悄只完成其中一项。身体生成路径保留逐项授权与审片。定位几何不是皮肤、可见性或遮挡语义真值，头发、脸颈交界、遮挡和轮廓自然度仍须实际评价。审片先看整图，再看由真实几何包围盒或生成 core 派生的同坐标局部；任一选中部位未完成则失败，证据不足则 unknown。

## 当前边界

当前形体结果支持改力度、恢复和导出；普通反馈继续编辑尚未支持，界面与规划均明确拒绝。恢复只证明像素复用，不伪造新的独立审片，也不承诺恢复后立即具备普通反馈资格。形体后的其它编辑互操作仍待完成。

几何保护精确不等于自然塑形；确定性形变场仍可能在头发、脸颈或遮挡处产生不自然的轮廓。局部完成与整图达标也不同；当前发布合同仍要求原质量轴及形体目标全部通过，不能用局部变化抹去母版已存在的整体光照问题。旧脸部生成路线已由几何操作替代，历史失败图片与费用保持原记录。

### 脸部形变场：历史与当前实现

**作废（0.7.3 及以前，仅作历史记录）**：逐行扫描线单调逆映射把整段收窄压在外侧 2.5% 脸宽过渡带里。真实 662 U、amount=.3、最大控制位移 9.99 原生像素时，实测前向奇异应变 [0.714, 2.026]，最坏处约 2.0 倍横向拉伸；其 required_outer_ramp 75.46 原生像素远超 admitted_outer_band 27.95，构造本身不可行，且在内侧加宽会折返成负 Jacobian。该构造已由下面的网格权重形变替换，上述数值不再描述当前实现。

**当前（0.7.4）**：眼轴对齐规则网格上的有界调和权重。网格 pitch = face_grid_pitch × mesh_pitch_fraction × face_width（真实 662 为 6.708 原生像素、84,096 节点、212 个 handle；真实 685 为 10.426 像素、101,442 节点、206 个 handle）。下巴轮廓每行最近网格节点作为 handle 携带该行承认的位移，保护区 P、包络之外与网格边界为零锚点（anchor_margin_cells=1 腐蚀），自由节点最小化 Dirichlet 能量（scipy.sparse.linalg.spsolve）。调和场的极大值原理使场受边界数据界定，因此 **不可能过冲或折叠**（Jacobian 恒正由构造保证，而不是事后检查）；这也是相对薄板样条／有界双调和（实测在真实 662 上过冲至 12.3 像素并折叠、Jacobian 0.18–0.51）与 ARAP（需静止配置与旋转拟合）、Green Coordinates（需笼边界积分）的选型理由。采样为 cv2.remap（INTER_LINEAR／BORDER_REPLICATE，96 行分块），真实 662 采样 0.4–1.0 s、685 0.7–1.8 s（4688×7028，RGB 与 G 各一次，随机器负载浮动）；建场 4.9 s／14.2 s，其中含下文三种应变口径的全场度量（只算面积比的那一轮为 3.2 s／6.7 s，审计口径的代价在此如实记下）。

**应变口径（不再用单个「应变」数说话）**。stats 同时记录三类量，strain_metric 写明各自是什么：

| stats 键 | 量 | 口径 |
|---|---|---|
| forward_strain_min／max | 检查用的**面积比倒数** 1/det(ds/dx) | 采样 Jacobian 行列式；natural_strain_bound_met 与限幅器以此为准入门槛（判据比较 jacobian_min／max，forward_strain_* 是它的倒数，读法见下方口径交代） |
| principal_stretch_min／max | 正向形变梯度 F=(ds/dx)⁻¹ 的**主拉伸** | 中心差分（O(h²)）估计 |
| principal_stretch_envelope_min／max | 上述主拉伸在四种单侧差分组合上的**最大包络** | 保守上界，仅审计用，不作为门限 |
| central_area_strain_min／max | 面积比倒数的中心差分估计 | 交叉参照 |
| unlimited_* | 未限幅（strain_limited_fraction=1）时同名量的实测值 | 让「如果足额交付会怎样」可复算 |

真实 662 U（amount .3）：面积比 [0.800000, 1.197021]、主拉伸（中心差分）[0.802459, 1.170524]、包络（四组合单侧差分）[0.784218, 1.210975]、未限幅面积比 [0.772547, 1.240443]、未限幅主拉伸 [0.774763, 1.207089]。真实 685 U：面积比 [0.811540, 1.250000000]（上限精确值 1.250000425）、主拉伸 [0.838594, 1.161479]、包络 [0.806420, 1.250092]、未限幅面积比 [0.781203, 1.317890]、未限幅主拉伸 [0.811430, 1.201170]。

**判定容差与比较对象**：判据只有两条，`natural_strain_bound_met` 里逐字写着——采样 Jacobian jacobian_min ≥ 1/1.25 − 1e−6 且 jacobian_max ≤ 1/0.8 + 1e−6，以及**中心差分**主拉伸在 [0.8 − 1e−6, 1.25 + 1e−6] 内。比较对象是**原始量**（Jacobian 与中心差分主拉伸），不是它们的倒数，也不是单侧包络；`stats.strain_metric` 把这两条写成 `bound_keys=['forward_strain_min','forward_strain_max']`、`principal_discretisation='central_difference'`，并把单侧包络标成 `envelope_role='conservative_audit_only_not_enforced'`。

**三处「超窗」数字的口径交代（同母版同命令可复算，均不改变门槛判定）**：
1. **685 面积比上界 1.250000425**：`forward_strain_max` 是 `1/jacobian_min` 的倒数表述，而 jac_min=0.79999973；判据读 jac_min 本身，0.79999973 − (1/1.25 − 1e−6) = 7.28e−7 > 0，原始量在窗内。倒数的 4.25e−7 超出量是 float32 对「已达标 jac_min」的舍入，不是越窗——面积比上界请按原始 jac 读，不按倒数读。
2. **685 包络上界 1.250092**：本轮逐组合复测，它等于**前向差分**组合的主拉伸（1.250092），即单侧差分的保守放大；同一场的中心差分为 1.161479。它只出现在审计字段，不进判据：拿最陡像素上的一阶差分当门限，会让真实力度替估计量误差买单。
3. **662「后向差分主拉伸 1.275156」**：在同一母版、同一交付场上逐组合重测**得不到这个数**——交付场 forward 1.201073、backward 1.210975、x 前/y 后 1.183557、x 后/y 前 1.179381、中心 1.170524（四组合最大值即包络 1.210975）；关掉限幅的未限幅场 backward 1.257362、forward 1.245469。因此 1.275156 不是当前 stats 里任一已命名量的取值；门槛判定不受影响（判据只读面积比与中心差分），审计面上最接近的是包络 1.210975（交付场）与 1.257362（未限幅场）。

这三条口径不是口头约定：`tests/face_contour_deform_smoke.py` 的 `test_only_the_area_ratio_and_the_central_principal_stretch_gate_the_bound` 在合成 fixture 上固定住它——该 fixture 的包络 [0.795253, 1.262080] 已经越窗，而 natural_strain_bound_met 仍为 true，且该判定可由 jacobian_min／max 与中心差分主拉伸按 1e−6 容差逐位复算；任何人把包络或倒数改成门限，这个用例都会红。

**界面显示的力度口径**：界面同时显示请求强度（requested_amount）、实际交付比例（delivered_fraction_of_request）与限幅系数（strain_limited_fraction），三个数值都取自保存版本形体回执的 stats，界面只显示不重算——取值在 `shaping_inspection.delivery_fact()`，`qt_workbench` 的力度字段与 tooltip 绑同一来源；没有回执或字段缺失时显示未知，不用界面里的 amount 反推交付比例。

**限幅器与其代价（本轮唯一实质残差）**。调和场的峰值分形率比朴素线性坡高约 1.8 倍（真实 662 峰值梯度约 0.294/px 出现在原生 (2420,2553)，该处到保护区距离仅 32.6 像素，而 6δ=60 像素的坡至少需要 40 像素），因此在真实母版上「面积比与主拉伸同时落在 [0.8,1.25]」与「足额交付请求力度」互斥。当前默认 strain_limited_amplitude=True：交付「两种口径都进窗」的最大幅度比例，比例本身写入 strain_limited_fraction 与 delivered_fraction_of_request，窗口阈值（0.8／1.25）与 attainment 门限（0.90）一行未改。代价是力度交付 84.3%（662）、82.3%（685），低于 attainment 0.90，于是质量报告在真实母版上按事实判 target_attainment 失败。是否接受这一交付比例、或接受越窗、或改窗口／几何，属产品决策，不由实现方私自决定；逐行压窄坡宽让整场进窗会同时把用户请求的力度偷偷缩小，按本文件禁止的做法不予采用。

**行跳变：读数修正＋定位加固（本轮关闭）**。旧读数 maximum_adjacent_face_row_change 报 1.489（662）／1.488（685），看似沿行抖动，实为「在同一格列内读差值」的产物：网格 handle 每行落在最靠近该行轮廓的那个节点上，轮廓沿行侧移一个格距时 handle 也换列，于是同一格列里出现 0／满值相邻（662 在第 54 列第 168→169 行之间 9.9884 原生像素，685 在第 241 列第 194→195 行之间 15.5178）。真正的行方向量是**每侧的控制序列**（按网格行索引、不按列）：改回该口径后实测 **0.2068（662）／0.1554（685）**，而交付位移场自身的相邻原生行变化只有 **0.2583／0.2149 px**（旧 0.7.3 构造的逐行剖面是 0.77 px），即轮廓边缘没有锯齿或抖动的来源，新场反而比旧构造更平缓。三个读数同时记录、口径逐项命名：`maximum_adjacent_face_row_change`（门限量，每侧控制序列）、`maximum_adjacent_face_column_change`（旧读数，仅审计，含节点换列信号）、`maximum_adjacent_field_row_change`（交付位移场的相邻原生行变化，px/行），描述符在 `stats.row_change_metric`。同时把 handle 定位从「最近的那个节点」改为「本行最近可用节点」（`handle_node_search_cells=3`）：原先最近节点若落在腐蚀后的安全带边界或锚点格上就整行丢弃该控制，会让相邻行独担全部压窄；现在控制保留在本行、侧移到最近可用列（两个真实母版上未触发任何丢弃，属防御性修正）。**力度与轮廓保真度均未让步**：交付压窄 8.4814 px／12.8665 px、限幅系数 0.849130／0.829145、attainment 0.8429／0.8227、应变 [0.800000,1.197021]／[0.811540,1.250000] 与修正前逐位相同，因此这次 row_change 转绿不是靠降低整体力度换来的。第三张真实母版 669 在盘上只有 0.7.2 的证据 JPEG，没有 detections.json 与 master.npy，产出检测需运行人脸检测模型，故本轮真实案例为 2/3。

原生源、生成及显影资产仍由当前 `photo_appearance` 创建和校验；几何资产使用独立的 `cosluma_geometric_appearance.v1`。统一 `appearance_assets` IO 按严格类型分派，当前结果唯一指针仍是 `options.photo_appearance`。新增几何操作不改写 U 的发行者或 receipt；原生真实算法变更仍按其 producer 合同使相应旧输入失效，不使用旧 SHA 例外或旧执行器。

统一 IO 可在当前进程内复用几何资产已经完成的数学验证。每次权威读取仍核验有限文件闭包的内容 SHA、绑定、操作和当前验证器、数值运行环境身份；内容相同的复制目录也先独立核验。磁盘旗标和界面事实均不授予读取权限。文件损坏、内容重签、额外文件、算法或运行环境变化必须重新验证或拒绝，不能把旧证明改为当前有效。

规划和执行可在一次操作内持有已保存父版本输入大文件的系统读保护。仅本地 Windows NTFS 支持：首次实际读取 SHA 后，持续持有拒绝写入和删除的文件句柄，每次复用核对当前路径与句柄身份；离开操作即释放，下次重新读取。登记输入根只是性能范围，不是授权。每个边界仍检查完整目录清单、元数据、绑定和当前代码／数值运行环境；新候选、复制目标和任一临时发布目录均不复用这个字节观察。其它文件系统或不可支持的平台继续实际读取，已有写入冲突明确失败，不降级为时间戳证明。

几何资产的 U 若来自显影，热命中前也核验其操作记录、显影发行者和当前参数合同。原生资产已有的数值 memo 不代替这些额外依赖检查；复用证明不能使过期的显影操作恢复有效。

界面在后台核验父版本和候选，调整幅度及刷新按钮不在主线程读取完整数组或复算形变。浏览事实随版本、文件、运行环境变化失效；采用前再做一次后台权威核验，并在提交选择时核对保存记录和当前交互状态。选择账本忙碌、取消、未保存编辑或迟到回调均保留当前选择；忙碌时不在界面等待锁，用户可重试采用。

离线模型夹具、实际模型效果、各部位自然度、当前独立安装和人工接受分别验证。离线通过不证明瘦脸或瘦身自然；大画布和生成纹理不证明新增相机细节。

## 公开任务合同

使用现有 `POST /api/tasks/plan`、`POST /api/tasks/start` 或 CLI `task-plan`、`task-start`。请求为 `existing_reference`，提供保存父 `parent_run_id`、原图 `source`、真实 U 预览 `reference`、父版本 `sample` 和原 `editing_request` 五字段。已有 `options.shaping_state` 时，U 为其 `base_appearance`；首次为父版本 `options.photo_appearance`。不能混用 `editing_iteration`、`editing_autofinish`、Beauty 或源域像素控件。

apply 附加 `shaping_request={"action":"apply","parts":{"face":0.3}}`，服务 `text_vision`、`visual_review` 均为 true。部位仅 `face`、`waist`、`arms`、`legs`；数值有限且在 0..1，零项不授权，空 apply、布尔值及未知字段拒绝。脸部仅单独执行；身体部位可组合。实际请求仍需保留父输入和原创作要求。

restore 附加 `shaping_request={"action":"restore"}`，两项服务均为 false，图像和视觉预算全零。只有严格受检的恢复能使用已冻结原图身份而不读取缺失 RAW；U 文件和绑定必须存在，其它任务的输入核验不放宽。

持久状态只在 `options.shaping_state`，当前像素仍唯一由 `options.photo_appearance` 选择。发布父 A 与实际输入 U 分别绑定，不修改旧 producer、receipt 或授权身份。已启用的当前资产必须是真实从 U 产生的区域候选。

行为检查：`tests/run.py photo_shaping photo_shaping_geometry face_contour_deform geometric_appearance appearance_read_scope appearance_proof_cache face_shaping_preflight shaping_portable shaping_ui shaping_inspection_ui shaping_quality saved_result_selection`。这些使用真实规划、几何、采样、会话、像素、Qt信号和保存路径，只模拟模型边界。CPU 数学验证保存的形变资产不属于定位或生成模型调用，恢复输出始终直接选择原 U。

## 客观验收度量

`scripts/shaping_quality.py` 把当前修图评测共识落成可复算的六项度量，全部由一次受检映射和它产生的像素算出：不调用模型、不写工程、不产生新的授权。

| 项目 | 量什么 | 判定 |
|---|---|---|
| target_attainment | 请求位移与实际最大控制位移（力度是否真的交付） | 交付/请求 ≥ 0.90 |
| untouched_regions | 编辑支持域之外是否出现任何改变像素 | 硬门：域外改变像素必须为 0；amount 0 时必须零改动 |
| texture_retention | 支持域内高频能量保留率（重采样是否抹平纹理） | ≥ 0.80 |
| tonal_neutrality | 支持域外 ΔE（几何重采样不该改色）；域内亮度变化只记录不判定 | 域外 ΔE 必须为 0 |
| boundary_seam | 边界梯度与未触碰环带梯度之比 | ≤ 1.6 |
| geometric_naturalness | 面积比倒数（准入门槛）与主拉伸（中心差分）、单侧包络（审计）、未限幅值、行跳变（每侧控制序列／旧格列读数／交付场三口径） | 面积比**与**主拉伸都在 0.8–1.25 且行跳变（每侧控制序列口径）≤ 1 px |

真实 662 U（amount 0.3，当前网格权重形变）：域外改动 0 像素、域外 ΔE 0、接缝比 0.9994、支持域高频能量保留 0.9196、面积比 [0.8000, 1.1970] 与主拉伸 [0.8025, 1.1705] 均进窗、行跳变 0.2068（审计口径 1.4891、交付场 0.2583 px/行）→ geometric_naturalness 通过；力度交付 8.481/10.062=**0.843 < 0.90** → verdict=fail 只剩 target_attainment。真实 685 U 同构：交付 0.823、行跳变 0.1554（审计 1.4884、交付场 0.2149）、高频保留 0.841、接缝比 0.989 → 同样只剩 target_attainment 失败。amount 0 时六项全过且像素零改动。旧构造在同一 662 上是力度 0.993、高频保留 0.792、应变 [0.714, 2.026]；两轮失败项不同，不能互相替代。

报告 schema `cosluma_shaping_quality.v1` 自带 `report_sha256`、`verdict`、`failed_items`，并显式保留 `artistic_acceptance=false`、`human_acceptance=false`、`model_inferences=0`；度量通过不等于艺术或人工接受，也不替代同视口 A/B。
