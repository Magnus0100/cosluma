# 原景增强与局部高清编辑

原景增强保留原建筑、主要物件、透视和人物位置，以原尺寸原片作为人物和可见背景的细节基底。它允许调整原景光色及一个明确选择的背景区域，不等于完整换景。严格保留背景与允许换景仍是不同选项。

## 制作方式

桌面默认新建参考任务使用原图驱动的美术设计：`create_reference + enhance_source`且未请求局部ROI时，自动选择`reference_role=source_conditioned_design`。API执行同一当前任务合同；普通参考、同照校准及显式区域编辑按各自声明的用途检查。用户提供的人工精修样张是质量与审美标杆，不是默认必需输入，也不是逐像素或1:1复刻目标。仍须填写希望的光色、肤质和氛围，让实际原图走完整流程达到目标质量；不能用“没有人工参考”解释默认成片只有基础调色。

在快速制作或专业页填写角色、作品／版本说明和希望的效果，选择“原景增强”。角色留空时不猜角色能力；已有资料是用户声明，不冒称软件联网识别。无特效要求优先，人物身份、妆造、姿态、手势、服装和相机保持。

“原景精修推荐”是可选风格，不是新任务的隐式约束。新任务默认只使用用户 brief、原片和当前工作流；选择推荐后才会启用它的肤色关系、材质和氛围目标。推荐不指定统一肤色或冷蓝滤镜，也不自动增加角色法术或雾叶实体；“只修衣服”“手不要动”“保留彩灯”“无特效”等明确限制优先。现有风格选择可退出推荐，不增加独立控制面板。

推荐目标与用户原文分别冻结，记录产品来源、版本、内容身份和实际可编辑覆盖文本。已打开的旧任务保持原合同；选择推荐的新任务才会写入推荐合同。已有推荐成片按当前算法重制时，需核验保存的同源合同后继承推荐，新增生图仍为0；普通打开、导出及旧无推荐任务不会补许可。

先检查计划，查看将保留什么、增强什么、主效要求及实际图像提交上限。创建参考首版只允许一个全局候选，避免多候选切换带来局部坐标和主效归属不一致。已有参考默认不新增生图；主动开启单区精修时，计划会明确列出全局参考0次、局部最多1次，本机GPU推理与外部服务分别显示。

确需局部内容时，显式开启最多一个区域，在原片上选择背景范围。核心宽高上限768像素，模型画布为1024×1024并包含周围上下文；原图边缘的padding不授予写入权限。区域必须完整位于人物覆盖之外，并离人物至少32个原生像素。执行前还会按原生alpha核验，不用缩略图近似代替。

主效在全画布只定义一次。局部描述应说明本区负责什么；不要在每块重新生成整个人物、完整场景或一套重复蝴蝶。已有背景或参考内的效果也不能无条件再叠一次。是否符合角色、效果是否成立，需要在实际保存图中检查。

## 同一条生产链

默认本地单候选、非延后选图的无ROI路线为：`检查并冻结原图驱动的创作方向 → 源Beauty并冻结结果 → Qwen仅以原始RAW生成一次设计参考 → 复用冻结Beauty，原生人物／背景重建与当前T/B/S、边界准备 → 经严格配准与有效域门核验的源图引导局部光色系数 → 原尺寸保存与审片`。

源Beauty只依赖原片，可先使用启动时已预热的服务；完成并拥有冻结结果后，再按资源交接策略把GPU交给本地Qwen，下游不因参考返回而再次推理Beauty。Qwen条件始终是原始RAW，不改用美化图。已有参考路线和远程服务的异步Beauty重叠策略保持原样。Beauty在生图前失败或取消时尚未提交Qwen图片，没有生成候选可恢复，应在配置或资源就绪后重新检查任务。

`source_conditioned_design`的新建任务预算为全局参考1次、参考纠错0次、独立效果图0次；不携带区域任务、旧恢复证明或多候选分支。计划阶段参考SHA为空，并声明生成后绑定；执行后核验实际参考输出SHA、原图来源、Qwen单图条件和真实任务ID，再冻结有效参考身份。已有参考继续使用此用途时，也必须具备相同原图生成的真实provenance，新增生图为0次。来源核验通过不等于图像已配准，配准质量和有效区域由实际worker检查。

原片始终拥有几何和原生纹理；生成参考提供美术设计与低频影调／局部色彩映射依据，不直接把参考RGB贴进人物。后续CPU算子与可选同照校准共用源图引导的系数应用机制，但不将AI设计参考冒称人工精修的同一张照片。配准、覆盖或局部映射支持不足时保留源图并报告缺口，不能放松门槛或伪称已达到质量目标。

原图驱动任务采用已检查的原景精修推荐，或用户明确要求去皮肤杂光、统一肤色时，会冻结脸、手臂和手的分域许可。可靠脸部皮肤作为当前光照下的颜色锚点，手臂接受有界低频修正，手接受共同白平衡，过渡放在腕部内；不会将手和指甲逐像素改成脸色。保留几何、掌纹、局部阴影及指甲相对色彩。未授权、保留彩光的明确要求和旧保存版本均不隐式启用。语义不确定的外边仍可能保留杂光，应在原尺寸审查，不越入琴面等物件隐藏残留。

场景明暗场还会检查原片中的手与前臂接触是否具有可靠的同材质连续证据，避免解剖标签之间的明暗硬切。延续的是有界照明修正，原片RGB和纹理不被空间模糊；真实色光边、手套、琴或衣物遮挡以及无证据孤岛不跨越。没有直接参考观测的区域记录为基于源图连续性的估计，不冒称新增对应点。是否自然仍须检查完整手腕、掌纹、指甲、皮肤阴影和道具边缘。

显式单ROI内容编辑是另一项检查选择：`创作方向与全局参考 → 原生人物与背景 → 必要单区生成 → 背景锚定与许可域合成 → 当前T/B/S及边界受光 → 原尺寸保存与审片`。它不与上述显式参考用途混用，额度和写入权限按本页的局部合同单独核验。

低分辨率参考主要提供整体光色方向；已有原片纹理不整图降清后重画。局部模型只接收一张局部照片与局部指令，不把整个人物图和全景创作提示带入任务。权限蒙版保留为本地诊断，不作为普通照片传给编辑模型，以免被画成白框。局部结果在图像域裁切，避免将通用8倍latent裁切坐标误用于Qwen2.1的16倍latent。最终写入权限由CPU合成器落实。

源背景已有观察、半透明F/B估计、区域生成和未知环境分别记录来源。不透明人物背后未观测的背景不作为细节供体；不移动人物后假称露出的新背景来自原片。背景变化会核验环境身份和下游准备，不能直接沿用失效快照。

## 保存、预算与恢复

区域生成独立于初始参考、参考纠错和独立效果预算。只有新检查计划显式授予时才有一次区域额度；普通打开、保存、复制、已有参考重制与最终本地修复均不续发额度。原始请求、条件图、输入SHA、实际工作流、响应ID及生成结果保留。

提交预留持久记录在模型请求之前。超时、取消或提交结果未知不会自动重发；失败保留父版本与已生成证据，不把不完整结果设为最新作品。成功结果冻结到保存版本的资产闭包，预览、原尺寸ROI、全图和portable使用同一套资产。

模型已返回但内容不符合局部任务时，保留原始图和真实提交数并拒绝合成。不能放宽门槛把完整人物图贴进背景，也不能重置额度。修正策略后可主动检查一个新的单区任务，它使用新版本自己的独立额度，原失败记录保持原样。

已有完整返回结果时，可选择“复用已生成局部结果继续合成（不生图）”。检查计划核验原片、参考、要求、实际单图输入、任务ID及八项资产身份，冻结零新增提交的复用证明。模型原始画布与许可区保留；新的CPU许可区可在该已知画布内显式移动，执行时仍核验人物32像素安全边带。这样可以保留越过旧许可边缘的完整效果，而不重新请求模型或修改旧失败记录。

局部曝光归一化从未编辑背景锚点估计，最大补偿±2EV；结构相关性和残差门保持独立，不能凭亮度补偿把错画布放行。归一化后的效果、原生区域接缝与纸质感仍需实际审查。

若独立worker在任何模型提交之前失败，可以显式选择“复用参考并恢复未提交局部步骤”。新检查计划必须证明原区域额度尚未消费：原任务、原片、已生成参考、角色和区域一致，journal为`failed_no_submission`、提交数为0、没有开始传输及任务ID。提交前在原journal锁内复核并保留失败历史；并发续作只有一个能消费。结果未知、已经提交或已完成的步骤绝不续发额度。该例外不重新生成整体参考，也不扩大普通已有参考任务或最终修复的预算。

原尺寸检查可请求美化前原片基线与保存成片的相同坐标窗口。对照来源和已包含的源精修如实标示，不把代理预览称为原尺寸。技术检查通过只证明范围、身份与一致性，不能代替人工确认角色主效、原景结构、妆造、纹理及过渡自然。

## 当前范围

### 可选校准：对照同一张照片的精修成片

在“已有参考＋原景增强”中，可显式勾选“对照同一张照片的精修成片”，对应`reference_role=same_photo_finish`。这是可选校准，不是默认原图流程的前提。原图是几何与原生细节载体，用户精修图只提供光色标尺；该用途不能同时申请区域生图或沿用旧的生成恢复授权，新增生图预算始终为0。检查计划冻结双方SHA和用途，并如实显示配准尚未执行。

执行时先准备当前原生人物与场景，然后核验同照特征、覆盖与变换健康度，在最终组合画面上拟合源图边缘引导的局部仿射色彩系数。参考RGB不直接贴入成片，原图像素坐标与alpha不移动。系数的局部增益受约束；出显示色域时沿原像素到映射像素统一退量，避免逐通道硬裁造成色带。

冻结后的系数、用途和实际配准回执随工程保存，整图、原尺寸ROI和显式缩放预览使用同一算子。普通重开不再配准或拟合；明确重新准备时先移除旧算子，再基于当前未套同照光色的组合画面拟合。原生高频由源图决定，但色彩映射会改变其对比和响应，因此不声称纹理逐像素不变。

这不是自动分材质、恢复真实灯光或拆出透明雾叶图层。裁切外的光色延拓是外观估计，局部液化、新增发丝和前景实体细节不由该算子恢复；须按实际原尺寸结果审查。

同样，默认原图驱动路线中的局部光色算子只能改变已有像素的低频外观，不能凭空生成新的薄雾实体、红叶、发丝或道具。生成参考里出现这些内容不等于原生成片已合成它们；若源图没有对应内容，必须有明确授权和实际消费的内容资产／生成阶段，否则保持未履约，不能把色彩改善说成雾叶已经完成。新增内容的许可与预算也不能从光色合同隐式取得。

当前合同与CPU回归只能证明输入、范围、来源和冻结回放边界。新的RAW是否达到用户要求的冷蓝环境、干净脸肤、局部发丝冷光和空间层次，仍须由该RAW的实际新任务、保存全图与原尺寸窗口验证；不能用此前其他照片的成功案例或人工样张本身代替。本页不宣称新琵琶照片已经达到艺术目标，最终人工批准另行记录。

桌面异步生产链在独立本地Python进程执行同一CLI；原生计算异常记录为任务失败，保留输入和旧作品，不自动重试。此隔离不等于已定位所有原生异常原因，也不改变图像生成预算。

界面预热与独立制作进程通过本地受控通道使用同一美化服务。状态、实际服务身份、提交、进度、取消和GPU阶段释放保持同一所有者；只有真实驻留且配置一致的模型才按已加载状态计算增量。GPU互斥卸载后如实恢复冷加载预算，预热、卸载和重载分别记录，不以历史成功结果冒充当前驻留状态。

这是单区域、有上下文的受控编辑，不是MultiDiffusion或任意7K联合扩散。上下文不能保证模型不移动结构；几何／内容漂移不能靠羽化修好。高分辨率容器也不代表恢复了原图中不存在的细节。

角色效果可以是非发光的情感意象，不默认法阵、血腥或全身描亮边。主效未实施或证据不足会保持未知／待审，不能因节点成功而标为已完成。各阶段实际用时与缓存命中写入当前账本，未测量的区域路线不给固定ETA。
