# 当前人像美化流程

BeautyGRPO 是当前人像美化组件。它生成完整脸部外观，默认强度 100%；自动检测可见人脸、生成 ROI，回写原生画布并按实际遮挡融合。它不修改人物 alpha。保存后的预览、重开和导出消费同一冻结图层。

安装配置可用 `vae_model_root` 指定 VAE 的独立存储位置。该组件仍须逐文件匹配已核验官方清单的大小与 SHA，绑定到安装校验记录；运行前检查其路径和文件身份。推理明确从该位置加载 VAE，并记录 transformer、VAE 与 LoRA 的实际位置。完整上游安装资料与已冻结提示词的编码来源不等于每次推理都要加载的权重，迁移时分别核算。

`原片 / RAW → 解码及一次显像 → 人脸定位与解析 → 完整脸 ROI → BeautyGRPO → 原生坐标回写 → portrait_beauty_layer.v1 → 场景与人物光色统一 → 保存`

普通导入参考的原生工具按检查计划准备 Beauty；scoped 创建不强制此步骤；本地原片编辑可以消费已拥有的冻结美化层。强度 0 为原片，1 为生成外观。模型采样为 1024，高清回写不等于生成了相机原生分辨率的细节。

当前唯一执行后端为 `nunchaku_cuda`，使用固定 Kontext INT4 r32 权重与 BeautyGRPO LoRA。采样为 28 步、guidance 2.5、seed 42、LoRA scale 1。原 offload 声明仅属于现有权重安装核验身份，不选择运行分支。

基础模型按实际组件核验：保留完整官方下载清单作为来源证据，安装核验不读取、不要求存在已经被 INT4 transformer 替代的三个 BF16 权重分片。CLIP/T5、tokenizer、VAE、配置和 LoRA 仍须通过当前组件核验，INT4 模型仍按固定官方 SHA 独立核验；生成流程没有 BF16 transformer 回退。

模型 Python、底模、LoRA、SegFace 和五官定位注册表由当前安装配置提供；配置选择和安装核验见 [安装指南](INSTALLATION.md)。准备使用独立模型运行时，日常读取已验证的提示词嵌入。缺少或过期的安装资源必须明确报告，不自动下载或换模型。

源图身份、ROI、采样结果、遮挡组合及用户强度都进入冻结图层。预览和保存使用同一份资产；失败和取消保留当前作品。模型运行、文件保存和艺术质量分别验证。跨人物、跨场景质量须用当前输出审查。

性能计时与复现方式见 [流程性能](WORKFLOW_PERFORMANCE.md)，软件执行入口见 [产品数据流](PRODUCT_ARCHITECTURE.md)。
