# 原片人物细节自动核验

软件在完整后期和“重新审片并本地修复”中检查人物细节。用户无需手绘范围或按照片调参；算法只使用当前匹配原片/成片审片窗口及独立保存的原片语义标签。

审片的 `retouch_missing` 只是观察，不能证明软件抹除了纹理。程序先核验所有母版、原片、参考和实际审片板，再在同一原生坐标检查人物内部。源语义表示位置归属，手标签不等于裸露皮肤，衣服标签不等于具体织物；未知位置不能用颜色猜测。

恢复依据是批准修饰后的冻结原片前景，不是未经修饰的原图、生成的人物或变形的参考。算法比较对数亮度的三个独立频带，把粗频带的响应作为当前明暗基础。两个相邻细频带在多个空间块中都显著衰减，而且原片存在可独立支持的结构时，才允许补回缺失的亮度细节。整体曝光、统一对比变化及可精确解释的全局通道仿色不能触发补纹理。通道仿色叠加共同低频曝光时，先验证 RGB 重建误差和曝光细频带能量，排除纯点操作造成的误恢复。噪声和不明确的随机纹理保持未解决。

初始尺度为原生短边 / 2048，最低为 1；候选逐次减半直到最低尺度。每个候选仅依据源 owner 距离、透明度、保护区和已审范围检查完整 Gaussian 内部支持，要求至少 128 个像素及 4 个各含 32 个支持像素的空间块。选择最大的可测候选后，才读取目标频带、噪声和损失；任何测量拒绝都不触发再次缩频。Gaussian 导数、噪声增益与细节恢复使用同一选定尺度，阈值不随照片调整。

缩频改变可观察的纹理范围。例如 6336 像素短边从约 3.09 缩到 1.55 后，两个细频带的峰值波长从约 20/40 像素变为约 10/20 像素。结果只描述所选可测频带，较大频带或太窄的 owner 继续未知。

修复保持当前色度、低频明暗、原生透明度和人物轮廓。材质、服装和背景边界向内限定；没有参考纹理、通用锐化或二次瑕疵恢复。后续雾气、效果或用户明确降噪造成的变化需要各自的处理资格，不能借人物模块补偿。

确认数值改善且没有明显低频漂移时，软件保存独立子版本，冻结亮度差异进入前景仿色之后、手动编辑之前。完整渲染、原生局部预览和工程重开使用同一冻结层。改变相关透明度或人物仿色剂量会使旧修复明确停用，避免沿用失效结果。

作品报告分别显示支持不足未测量、频带测量未定、数值与视觉诊断冲突、确认结构损失、恢复拒绝。每个 owner 保留窗口、尺度候选、支持像素和空间块、细频带相对响应及相关性。仅当两个细频带各有至少 4 个结构块、相对增益的 10%/90% 分位都在 [0.9, 1.1] 且相关性中位数大于 0.98，才说明所选频带响应保留。声明最终成片存在诊断冲突时，在已选尺度和支持范围直接测量实际浮点母版的频带，完整读取它自己的滤波输入；不会重新选尺度或尝试修复。后续图层使最终频带不再满足时，归其自身处理。

若确有合格的恢复候选，其写入范围内的实际母版还须与人物仿色端点数值对齐：各正通道的对数比差不超过 1e-6，零通道须完全相同。该限制防止人物恢复补偿后续雾气或手动效果，不用绝对 RGB 差掩盖暗部变化。

未确认损失或支持不足时，保留原像素与诊断摘要。原有的 fail/unknown 不会因此自动改成 pass。重复进入只读已有尝试和后续动作，不额外启动 worker 或请求 API。新像素需要新的整图、上下文和原生审片；自动审片也不代替用户的艺术质量批准。

冻结分析与审片通过生产文件的原始字节绑定身份。未改变算法的生产文件也不能被统一换行破坏身份；相应 Git 属性保留字节，公开源码、普通 clone 和程序包仍须逐字节核验。
